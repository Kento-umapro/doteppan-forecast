# どてっぱん 売上予報

本部運営8店の売上が、この先60日でどの日に上振れ・下振れしそうかを毎朝出すページ。
公開先 → https://kento-umapro.github.io/doteppan-forecast/

## しくみ

```
ダイニー経営管理API ──▶ .cache/kpi.json ──▶ build.py ──▶ docs/data/*.json ──▶ GitHub Pages
   (日別の売上・客数・天候)      (円入り・非公開)      (係数を学習)     (指数のみ)
```

売上は掛け算のモデルで表す。

```
売上 = 水準(その時期の店の力) × 曜日 × 月(季節) × 暦(祝日/年末/お盆/休前日) × 近隣の催し
```

係数は毎朝ぜんぶ学習し直す。実績の少ない催しは `scripts/events.json` の `prior`（手入力の暫定値）
に引き戻し、実績が増えるほど実測が効くようにしてある（縮小推定）。だから走らせるほど当たるようになる。

- 曜日・水準・催しの係数は互いに絡むので、3周まわして収束させている
- 展示会は月〜木／金／土日で効き方がまるで違うため、同じ展示会でも曜日区分ごとに別係数
- 同じ日に展示会が何本重なっても「街に展示会客がいる」状態は1つなので、いちばん格の高い1本だけ採る

## 毎日の自動実行

`~/Library/LaunchAgents/com.doteppan.forecast.plist` が毎朝 **9:40** に `run.sh` を叩く。
（出数ダッシュボードの 9:05 のジョブと同じログインセッションを使うので、終わったあとにずらしてある）

手で動かすとき:

```bash
~/doteppan-forecast/run.sh
```

ログインが切れたときは、いったんブラウザを開いて本人がログインし直す:

```bash
node ~/doteppan-shussu/scripts/browser.mjs
```

## 催しを足す

`scripts/events.json` の `events` に1行足すだけ。`shops` を空にすると全店に効く。

```json
{ "from": "2026-11-03", "to": "2026-11-03", "shops": ["000500"],
  "tag": "maebashi-matsuri", "name": "前橋まつり", "prior": 1.3, "note": "実績なし・暫定" }
```

`tag` が同じものはまとめて1つの係数として学習される。`prior` は実績が3回たまるまでの暫定値。

## 公開してよい範囲

`docs/` に円の実額は一切書き出していない。出しているのは

- **平常比** … その時期・その曜日の平常を 1.00 としたときの倍率
- **水準** … その店の普段の平均日を 100 としたときの水準

円の実績は `.cache/`（gitignore 済み）にだけ置く。**`.cache/` は絶対にコミットしない。**
